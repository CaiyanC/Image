# 视觉素材标签与跨 SKU 检索设计

## 目标

在既有 `/assets` SKU 内素材管理能力上，补齐试点所需的受控业务标签和全库检索能力，使团队可以对首批 20 个 SKU 的素材进行统一标注、筛选与验证。

## 范围

本次只实现：

- 四个新增标签维度：`expression_tags`、`selling_point_tags`、`scene_tags`、`mood_tags`。
- 素材角色约束：卖点图至少一个卖点；场景图至少一个场景；氛围图至少一个氛围标签。
- 受权限保护的跨 SKU 素材搜索 API 和前端全库检索页。
- 开发环境独立端口验证，后端 `8002`、前端 `5277`，连接既有开发数据库 `product_knowledge_dev`；不写入现有素材数据。

本次不做：批量导入 20 个 SKU 的真实素材、图像向量检索、OCR、自动打标、生产发布。

## 标签规则

标签继续存放在现有 `product_assets.tags` JSON 对象中，保持向后兼容。

| 键 | 名称 | 试点受控词表 |
| --- | --- | --- |
| `expression_tags` | 素材表达 | 卖点图、场景图、氛围图 |
| `selling_point_tags` | 卖点 | 轻量便携、易收纳、耐用、导热均匀、保温、易清洁、安全、容量大 |
| `scene_tags` | 场景 | 徒步、硬核露营、车露、家庭露营、雪地、森林、湖边、室内 |
| `mood_tags` | 氛围 | 硬核、温暖、自由、专业、精致、极简 |

卖点标签在试点阶段允许由具备既有 `tag.edit` 权限的人员选择受控词表；后续可将其映射到产品元数据库的 TOP5 卖点。风险标签的既有 `media.review` 限制保持不变。

## 搜索与数据流

新增 `GET /api/assets/search`，只返回调用者可读取范围内的素材。接口接受可选的 SKU、分类、审核状态、授权状态、渠道以及上述四个标签维度；多个过滤条件以 AND 组合，同一维度多个标签以 OR 组合。搜索结果按 SKU、分类、素材序号稳定排序，并包含现有完整素材字段。

前端新增 `/assets/search` 页面。用户可多选筛选条件，点击搜索后查看跨 SKU 素材卡片；点击卡片跳转现有 `/assets` 并预选对应 SKU。原 `/assets` 页面保留其 SKU 内上传、编辑、批量打标流程，并在标签面板中展示新增维度。

## 约束与错误处理

- 空搜索条件可查看全部可读素材，但默认限制 100 条，以防止大库全量加载。
- `limit` 范围为 1 到 100；不合法参数返回 422。
- 标签更新不满足素材角色约束时返回 422 和明确错误信息，且不修改已有标签。
- 检索不以标签 JSON 的数据库索引为前提；20 SKU 试点规模可接受。正式扩库前，再评估 JSONB/GiN 或规范化关联表。

## 测试与验收

- 服务/API 测试覆盖标签约束、跨 SKU AND/OR 过滤、权限和 100 条上限。
- 前端构建通过，页面可选择新增标签并显示搜索结果。
- 在 `8002/5277` 手工验证：对测试素材打标；按卖点、场景、氛围跨 SKU 搜索；检索到的卡片可打开对应 SKU 素材库。

## 20 SKU 试点验收口径

每个 SKU 至少有一条素材具备素材表达标签；若是卖点图、场景图或氛围图，分别满足对应的必填关联标签。试点检索题至少包括：按卖点找图、按场景找图、按氛围找图、按渠道和审核状态组合找图。
