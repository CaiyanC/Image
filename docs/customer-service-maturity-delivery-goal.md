# 智能客服成熟度交付目标

## 目标

把当前的“能回答部分字段和 QA”的客服，持续收口为可实际接待客户产品咨询的智能客服。它应由 DeepSeek 理解完整自然语言和会话上下文，再以同 SKU 的产品数据库、产品 QA 与文件知识库为证据生成自然回答；不是依赖固定问句、SKU 特判或关键词路由的规则客服。

本目标的完成定义不是旧 A/B/C/Supplemental 或某一批 HTTP 用例通过，而是客户面对真实产品咨询时可以稳定得到有帮助、可读、可核验且不过度承诺的答案。

## 昨日约定的工作重点

1. 提升正常产品对话的成熟度。客户不一定只问“材质是什么”；系统应能理解“两个产品哪个更适合两人徒步”“这个产品出门前要注意什么”“哪些信息能帮助我决定”等自然问题，并真正作答。
2. 统一数据库、产品 QA 与文件知识库/RAG。已有同 SKU 资料必须被合理取回和总结；资料没有直接答案时要说明边界，不能拿同 SKU 的无关规格凑答案，也不能编造。
3. 做好比较、推荐与多轮。比较要绑定双方产品并使用与条件有关的真实证据；推荐要由 DeepSeek 理解需求、给出真实理由；多轮上下文只补充“哪件商品”，不能覆盖当前问题或串 SKU。
4. 让回答保持亲切、简洁、可直接发给客户。QA 命中不能机械照抄，也不能在润色时删除、加强或新增事实。
5. 优先修复成类根因，而不是逐句补规则。把真实 HTTP 发现的问题按语义预计划、实体绑定、检索、证据选择、生成、核验和会话仲裁聚类后，修复中央机制，再用新表达验证。

## 核心链路

```text
完整用户问题 + 当前会话中已确认的产品身份
  -> DeepSeek semantic preplan
  -> FieldContract / product_qa / comparison / recommendation contract
  -> EntityResolutionContract
  -> canonical SKU 或明确集合
  -> 同 SKU 数据库、QA、文件知识库证据检索与选择
  -> 生成
  -> grounding、完整性核验、亲切润色
  -> 客户可读答案
```

确定性代码只负责合同、实体唯一性、同 SKU 边界、数据有效性、敏感信息与低置信澄清；不得以硬字段匹配、固定问句或商品特判替代高置信的 DeepSeek 语义判断。

## 长期执行顺序

### 1. 正常对话与 RAG 优先

先处理客户最常见但不属于单一字段的问法：开放了解、使用准备、注意事项、适配判断、真实产品差异与购买决策。每个回答必须有回答问题的直接同 SKU 证据；同 SKU 但无关的内容不能作为答案。

### 2. QA 自然改写与知识融合

对原问法、口语改写、同义问法和带上下文的追问进行测试。QA 与文件资料的事实应融合为自然答案，但不得把部分词面相似误作语义等价，也不得漏掉同一条已选证据中相互依赖的安全、操作或限制信息。

### 3. 身份、比较、推荐和多轮

覆盖 SKU、完整名、唯一简称、真实歧义、未知商品及代词跟问。比较必须使用两个明确 SKU；推荐必须让 DeepSeek 从完整需求抽取条件并以候选证据解释；真正歧义必须澄清。

### 4. 字段与客户边界

持续盘点真实数据库、关联表、JSON 与文件资料中的客户价值字段。正式字段可查询时走 FieldContract；只有 QA 或 RAG 支持的事实走对应证据合同；内部、检索、实时或无效数据不得泄露或编造。

## 每轮工作方法

1. 用 UTF-8 HTTP 脚本生成一小批未参与修复的新表达，按产品、意图、知识源和会话状态分层抽样。
2. 保存并人工审阅问题、服务端实际收到的问题、完整答案、semantic preplan、合同、resolved SKU、evidence SKU、路由与最早错误决策点。
3. 把 FAIL、WARNING、REVIEW 按中央根因聚类；先补最小失败回归，再修复实现。
4. 运行受影响的定向测试与不同产品的 HTTP holdout；已稳定通过的同类问题不反复消耗大规模测试时间。
5. 只有源码相对稳定后，才运行完整回归、fresh dev 和发布候选验收。

## 可交付门槛

以下项目在 fresh dev `8001` 的真实 HTTP 人工审查中持续满足，才可进入生产发布：

- 明确 SKU、完整名称、唯一简称与多轮代词均绑定正确实体；错 SKU、跨 SKU evidence、无实体合同商品事实为零。
- 数据库、QA 或文件知识库存在有效同 SKU 证据时，不回答“没有资料”、不空泛、不漏答；无证据时给出问题专用的安全说明。
- QA 自然改写不照抄错误答案，终稿亲切但事实不漂移。
- 开放 RAG、字段、比较、推荐、类目筛选、歧义和多轮均有真实答案人工审查，而不只看 HTTP 200 或路由。
- 没有未分类 REVIEW、P0 或阻断 P1；所有本次答案变化和 WARNING 都经过人工阅读。
- `py_compile`、`git diff --check`、当前受影响测试、fresh dev 复测通过；源码精确提交并推送 `origin/dev`。
